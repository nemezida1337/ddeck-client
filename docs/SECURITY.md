# Безопасность DDeck

DDeck даёт удалённый доступ к **вашему собственному** компьютеру с DeepSeek Harness.
Это по своей природе полный операторский доступ: агент умеет запускать команды,
читать и изменять файлы. Поэтому безопасность здесь — не «дополнение», а основа.

## Что защищает DDeck

- **TLS с пиннингом.** При сопряжении приложение запоминает сертификат компьютера
  (отпечаток приходит из QR/приглашения) и отказывается доверять другому сертификату.
- **Одноразовое окно сопряжения.** Шестизначный код/QR живёт 5 минут, после успешного
  сопряжения окно закрывается и код нельзя использовать повторно.
- **Один телефон — одна запись.** Повторное сопряжение того же устройства обновляет
  запись, а не создаёт новые.
- **Админ-панель только с компьютера.** `/dsh-remote*` принимает запросы только с
  loopback и проверяет Host/Origin/Sec-Fetch-Site; через шлюз для телефона эти
  маршруты отвечают `404`.
- **Токены не хранятся в открытом виде.** На компьютере хранится только digest
  device-token; на телефоне — шифртекст с ключом в Android Keystore.

## Модель угроз (кратко)

- Сеть (домашний Wi-Fi, tailnet, интернет) считается **недоверенной**.
- Сопряжённый телефон считается доверенным оператором компьютера: отдельного
  ограничения прав у него нет.
- Контент, который отдаёт DSH (ответы модели, файлы, markdown, браузер), тоже
  недоверенный: он живёт в том же origin, что и интерфейс.
- Сам хост DeepSeek Harness, LLM-провайдер и настройки ОС — вне периметра DDeck.

## Что вы должны сделать

1. Сопрягайте только **свой** телефон и только по QR/коду, который видите на своём
   компьютере.
2. Не пересылайте QR, код или адрес панели третьим лицам: это ключ к компьютеру.
3. Используйте Tailscale или доверенную локальную сеть; не открывайте порт `3449`
   в интернет.
4. Регулярно отзывайте ненужные устройства в панели DDeck.
5. Храните release-ключ подписи приложения (см. `SIGNING.md`) отдельно от репозитория.

## Сообщения об уязвимостях

Если вы нашли уязвимость, **не создавайте публичный issue** с деталями эксплуатации.
Напишите владельцу репозитория приватно (контакт — в профиле GitHub) и дайте время
на исправление. В отчёте укажите версию приложения/плагина и шаги воспроизведения.

## Поддерживаемые версии

Бета: поддерживаются последние выпуски из GitHub Releases. Плагин и приложение
рассчитаны на одну версию протокола; при обновлении плагина обновляйте и приложение.
