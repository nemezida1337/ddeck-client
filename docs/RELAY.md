# Свой сервер (DDeck Relay)

Режим для тех, у кого есть VPS: телефон подключается к публичному адресу
сервера, а Mac держит **обратный SSH-туннель** к нему. Tailscale и обычный VPN
не нужны, входящие порты дома не открываются.

## Что нужно

- VPS с публичным IPv4/доменом и SSH-доступом (root или sudo);
- nginx **или** Caddy на сервере (или установите один из них);
- свободный публичный порт, например `3449`;
- SSH-ключ с Mac — без пароля в плагине.

## Установка

На Mac:

```sh
cd ddeck
./plugin/relay/setup.sh \
  --ssh relay-vds \
  --origin https://relay.example.com:3449 \
  --gateway-origin https://100.x.y.z:3449
```

- `--ssh` — хост из `~/.ssh/config` (или `user@host`);
- `--origin` — адрес, по которому телефон будет видеть сервер;
- `--gateway-origin` — текущий origin шлюза DSH (тот, что показывает панель DDeck).

Скрипт:

1. выпускает TLS-сертификат на публичный адрес, подписанный CA плагина;
2. копирует на сервер изолированный установщик;
3. настраивает **nginx или Caddy** отдельным блоком, проверяет конфигурацию и
   перезагружает только этот сервис;
4. поднимает обратный SSH-туннель;
5. сохраняет публичный origin в `~/.dsh/dsh-remote/origins.json`.

После этого **перезапустите DeepSeek Harness** — панель DDeck начнёт показывать
QR с публичным адресом. На телефоне просто отсканируйте его.

## Caddy

Если на сервере стоит Caddy, скрипт добавляет в Caddyfile отдельный блок с
маркерами `DDeck Relay`, проверяет `caddy validate` и делает reload. Существующие
сайты не меняются. Если Caddyfile лежит не в `/etc/caddy/Caddyfile`, укажите
`--proxy caddy` и поправьте путь вручную — скрипт не угадывает нестандартные
раскладки.

## Безопасность и откат

- Сертификат сервера подписан **CA плагина**, поэтому телефон по-прежнему
  проверяет тот же отпечаток, что и при прямом сопряжении.
- Туннель идёт по SSH; пароли и приватный CA-ключ на сервер не копируются.
- Перед изменением конфигурации nginx/Caddy скрипт делает бэкап и откатывает его,
  если `nginx -t` / `caddy validate` не прошли.
- Публичный `3449` можно закрыть файрволом, когда сервер не нужен; сам VPS
  остаётся доступен только по SSH.

## Ограничения текущего прототипа

- Туннель запускается как `nohup ssh`; автозапуск после перезагрузки Mac —
  следующий шаг (launchd).
- Публичный адрес лучше указывать как домен; IP тоже работает, но сертификат
  выпускается на конкретный IP.
- Прокси на VPS терминирует TLS и видит трафик; для DDeck Cloud нужен отдельный
  end-to-end relay.

## Проверка

```sh
curl --cacert ~/.dsh/dsh-remote/tls/ca.pem \
  https://ПУБЛИЧНЫЙ_АДРЕС/mobile-access/metadata
```

Должен вернуться JSON с `version`/`pluginVersion`; `/dsh-remote/status` снаружи
должен отдавать `404`.
